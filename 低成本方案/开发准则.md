# Git的使用

## Git初始化

**安装 Git：**

```
sudo apt update
sudo apt install git
```

**配置 Git：**

```
git config --global user.name "Your Name"
git config --global user.email "youremail@example.com"
```

**创建一个 Git 仓库：**

```
cd /path/to/your/project
git init
git remote add origin git@github.com:你的用户名/robot-brain.git
```

**流程：**

```
# 大脑（在文件夹）
cd /path/to/your/projects
mkdir robot-brain
cd robot-brain
git init
git remote add origin git@github.com:你的用户名/robot-brain.git
# 创建 README 并推送，建立关联
echo "# robot-brain" > README.md
git add README.md
git commit -m "init: 初始化大脑仓库"
git branch -M main
git push -u origin main
# 创建 dev 分支
git checkout -b dev	（-b创建并切换）
git push -u origin dev # 把本地 dev 推送到远程 origin 的 dev，origin 是远程仓库的默认别名，-u建立本地分支和远程分支的关联。
```



## Git规范：

**仓库管理-4个独立仓库（本地和github都要有）：**

```
- robot-brain（大脑）
- robot-cerebellum（小脑） 
- robot-cloud（服务器）
- robot-client（客户端） 
```

**分支策略：**

git仓库的main和dev分支本质是同一个文件夹里的两个不同版本状态。

main是稳定版本，dev是开发中的版本。

feature是各自的一个个的功能模块，如pid、motor_control、nav2、lidar等等。

hotfix是修复bug用的分支。

```
main        # 生产稳定版，只接受 dev 合并
dev         # 开发主分支，大家从这里拉功能分支，先合并到dev，main是最终版的
feature/*   # 功能分支，每个人自己开
hotfix/*    # 紧急修复分支，直接基于 main（生产出问题才用）
```

**提交格式：**

```
feat(模块): 新功能
fix(模块): 修 bug
docs: 文档
refactor: 重构
示例：
feat(小脑/接口层/控制板): 完成串口驱动
feat(小脑/接口层/控制板): 完成协议解析
feat(大脑/接口层/雷达): 完成2d雷达驱动，并节点化发布话题/scan
feat(大脑/算法层/导航): 完成2d地图发布话题/map
feat(大脑/算法层/导航): 完成nav2导航模块
```

**代码格式化：**

```
- C++：clang-format（Google风格）
- Python：black
- 其他...
```



## **日常开发流程**

```
# 1. 每天早上从 dev 拉最新代码
git checkout dev  # 切换到 dev 分支
git pull origin dev  # 从远程仓库拉取最新的 dev 代码

# 2. 创建功能分支 
git checkout -b feature/motor_driver  # 创建并切换到新分支

# 3. 开发过程中多次提交（按 commit 规范）
git status   # 看看改动了哪些文件，确认没有误改
git branch  # 看看自己在哪个分支
git add .   #添加当前文件夹内容到暂存区
git commit -m "feat(小脑/算法层/PID): 添加电机速度PID控制"
git commit -m "feat(小脑/接口层/控制板): 添加串口通信异常重试"

# 4. 功能完成后合并回 dev
git checkout dev
git pull origin dev  # 再拉一次最新，防止冲突
git merge feature/motor_driver --no-ff  # --no-ff 保留分支历史
git push origin dev

# 5. 删除已合并的功能分支
git branch -d feature/motor_driver
```
