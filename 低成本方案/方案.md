# **系统架构设计**

本文参考智元远征A2人形机器人旗舰款、宇树UnitreeG1人形机器人、宇树机器狗Go2、南华大学机器人智能底盘、幻尔智能机器人。

系统整体采用分层模块化设计，云端管理层、感知决策层、实时运控层、机电执行层。



**已有硬件**

幻尔小车机架（含编码器电机*4）、jetson nano、rk3568 4+64GB、2D激光雷达、深度相机、麦克风阵列、EtherCAT伺服电机

**软件移植**

大脑与小脑均采用docker进行开发，方便一整套直接打包移植，应用层->话题接口层->驱动层，移植后只需要修改驱动层即可

驱动层全用Lifecycle，算法层和应用层只用普通Node。

**优点如下**

1. 软件上与硬件完全隔离，可移植到任何性能足够的机器上
2. 可以按照自己的节奏走，完全不受限于他人
3. 收获个人机器人项目写简历上、完成企业实习写简历上、个人项目后续还可以用来给学校打比赛继承下去

一举四得，非常nice。

**目标如下**

使用现有设备完成所有功能，必须确保极高的移植性、扩展性、稳定性，完成后移植到公司底盘上。



## 核心问题

 jetson nano-交换机-rk3568+电机通信-stm32控制器

更新移植：jetson orin nx - 交换机 - rk3588+电机通信 - 控制器

目前小车是一体化的，大号的rk3568和交换机完全塞不进，但是stm32f4控制器有源码、原理图、通信协议解析。



方案一：

使用rk3568核心板+自画双网口底板，不使用交换机（或者微型交换机），优点是符合物理架构，性能足够。但是耗时太久了。

方案二：

采用软件模拟方式

物理上使用jetson nano-stm32控制器

软件上 【大脑docker】-虚拟以太网段-【小脑docker】-【控制器】



对应      大脑docker - 交换机 - 小脑docker - 控制器

大脑docker：原本就是这样配置的

虚拟以太网段：完全能够模拟真实交换机功能

小脑docker：原本计划小脑ros2就是使用docker的

控制器：可以是串口、EtherCAT、CAN都没问题



主要的应用部分均采用docker进行开发，移植是极其方便的，关于以太网和电机控制也只需要更改驱动接口即可。考虑到时间关系和移植方便性等等因素，我们选择方案二来解决问题。


大脑docker运行Ubuntu22.04无桌面版+ROS2 Humble，跑MQTT+WebSocket+WebRTC通信、YOLO+OpenCV视觉（YOLOv8n + TensorRT + 低分辨率 + 5Hz推理）、2DSLAM、RTK、系统监控、nav2、网络API语音转文本、网络API文本转语音、网络API LLM/VLM、任务树、PTP Master

小脑docker运行Ubuntu22.04无桌面版+ROS2 Humble（不使用PREEMPT-RT），跑MQTT/TCP通信、电机通信控制（与stm32控制器串口通信）、IMU姿态平衡、odom里程计、twist话题控制、BMS通信监控（与stm32控制器串口通信）。

使用jetson nano，4GB+64GB



当性能出现瓶颈时使用

{

大脑docker cpu0+1 2.5GB
小脑docker cpu2    0.5GB
宿主机+系统   剩余使用

}



刷机为ubuntu18的无桌面版，需要rviz2可以使用x11转发来做。(gazebo基本用不上)

# **云端管理层**

该层为面向管理人员的服务端，管理人员可轻松使用平台进行相关控制管理相关操作。

## 接口协议选择

| 协议          | 一句话定位         | 类比                               | 消息                                       |
| :------------ | :----------------- | :--------------------------------- | ------------------------------------------ |
| **MQTT**      | 轻量级“消息快递员” | 发短信（小数据、低功耗、可丢包）   | 控制指令和状态上报（轻量可靠）             |
| **WebSocket** | 双向“实时管道”     | 打电话（长连接、低延迟、双向通信） | 信令交换和实时数据推送（双向低延迟）       |
| **WebRTC**    | “视频流高速公路”   | 看电视（大数据、高带宽、连续流）   | 视频流、音频流、点云数据（超低延迟抗丢包） |

# **感知决策层**

该层作为整机大脑部分，负责机体的感知、决策、网关系统，采用驱动-节点接口-应用分层，Docker部署方便一键打包移植并隔离环境。

## 基础配置

1. 主控：Jetson nano 4GB+64GB+1Tops		升级->Jetson Orin NX 16GB+128GB+157TOPS

2. 传感器：奥锐达MS200 2D激光雷达、Aurora930 Deptrum® Aurora 930系列深度相机、R818 降噪板与环形六路麦克风阵列、RTK北斗定位模块

   升级->			3D激光雷达										户外深度相机															大功率功放与麦克风

3. 软件：Docker + Ubuntu22.04 + ROS2 Humble

## 软件架构

### 公共层

该层作为贯穿所有层的隐形支柱，负责安全、诊断、日志、配置、全局时间同步等公共功能。独立层

### 驱动层

常规Linux驱动编写方式，与ros无关。独立层

### 系统服务层

一些系统服务，与ros无关，如AP配网、时间同步。独立层

### 驱动接口层

由驱动文件加载+接口组成，用于隔离软硬件，方便移植。比如激光雷达-串口-接口话题 /lidar_2D， 激光雷达-网口-接口话题 /lidar_2D，激光雷达-网口-接口话题 /lidar_3D

接口话题不变，更改驱动即可。

### 算法层

面向对象思想的独立算法模块，可配置数据源，方便复用。如map模块、nav2模块、yolo模块、通信模块等。

### 应用层

使用接口层+算法层构建一个个应用APP，如网关系统、视觉系统、音频系统、导航系统应用功能。

算法层各司其职完成了核心任务链路的整合。应用层主要做的是顶层任务 + 决策 + 监控。

### 二开层

将功能节点封装为RPC接口，即使用http作为通信方式用于二次开发，屏蔽了开发语言的差异性，任何支持http的语言都可以进行二次开发。

### 任务层

该层以任务为单位，无论是应用层任务还是二开层任务，都需要放入该层注册，由系统状态机、行为树进行任务编排调度，是全局大脑。
同时可接入大模型（二次开发者）作为拟人角色使用RPC接口发布任务参与编排。如注册了电量低返航充电任务、巡航任务、检测任务，该层会执行巡航、中途调用检测、电量低时触发返航充电。它不再关注底层的“怎么动”（那是应用层的事），而是关注“做什么”和“按什么顺序做”。
该层由任务注册模块、任务编排模块（行为树BehaviorTree.CPP、py_trees）、调度仲裁模块构成。

| 系统         | 核心功能                                                     |
| :----------- | :----------------------------------------------------------- |
| **通信系统** | WIFI/5G - 加解密 - MQTT/WebSocket/WebRTC驱动 - 接口话题 - 实现指令接收与状态上报 |
| **传感系统** | 视觉（目标识别、深度检测）、音频（异响匹配）、建图（2D/3D SLAM）、定位（RTK/融合/里程计）、安全（BMS/电机/系统状态监控）... |
| **控制系统** | Nav2导航（发布`/navigate_to_pose`目标），并具备急停与遥控接管机制 |
| **交互系统** | 语音（语音转文字/文字转语音）、网络（传感与控制数据通道）    |
| **AI系统**   | 在线/离线大模型（LLM/VLM），通过Function Calling调用交互与任务系统 |

| **配置系统** | 全局配置文件管理，支持环境切换与热加载                       |

# 机电执行层

该层是物理接口，接入控制器，如CAN、EtherCAT、串口控制器等
