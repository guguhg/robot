订阅回调的两种处理方式

1.订阅到了直接回调处理逻辑

2.订阅到了回调更新最新数据，标志位置位，等定时器周期到了再做处理

### 1️⃣ 方式一：在回调函数中直接处理（同步处理）

- **原理**：ROS 2 的 Executor 每收到一个消息，就立即调用你的回调函数，函数内部完成所有计算、发布等操作，函数返回后 Executor 才去处理下一个消息。
- **特点**：
  - **实时性高**：数据一来就处理，延迟最低。
  - **逻辑简单**：代码直来直去，容易理解。
  - **阻塞风险大**：如果回调函数处理耗时（比如涉及磁盘 I/O、复杂运算、网络请求），会阻塞 Executor，导致**后续所有话题的回调都被延迟**，造成系统“假死”或丢帧。
  - **适用场景**：处理逻辑极轻量（如简单数据转换、状态更新）、对延迟极其敏感的控制指令（如紧急停止）。

### 2️⃣ 方式二：回调仅更新缓存 + 定时器周期处理（异步处理）

- **原理**：回调函数只做最轻量的事——将收到的数据拷贝到共享缓存中，设置一个标志位（`new_data_available = true`）后立刻返回。另有一个独立的定时器（Timer），按固定频率（如 50Hz）从缓存读取最新数据进行处理。
- **特点**：
  - **响应稳健**：回调函数执行极快（微秒级），绝不阻塞 Executor，系统吞吐量和稳定性大大提升。
  - **定时器频率可控**：你可以决定处理频率，比如传感器 100Hz，但控制周期只需要 50Hz，可以丢弃中间帧。
  - **数据可能被覆盖**：如果定时器处理速度慢于数据到达速度，缓存中的旧数据会被新数据覆盖，相当于“丢帧”（这在传感器数据处理中是可接受的，但在控制指令中可能不允许）。
  - **适用场景**：处理耗时任务（如点云滤波、图像处理、路径规划）、高频率传感器数据（激光雷达、IMU）、需要固定周期输出的任务（如控制循环）。

------

### 🆚 深度对比

| 对比维度                 | 方式一：回调直接处理                 | 方式二：回调缓存 + 定时器处理            |
| :----------------------- | :----------------------------------- | :--------------------------------------- |
| **延迟（Latency）**      | 极低（微秒级）                       | 较低（定时器周期级，如 20ms）            |
| **吞吐量（Throughput）** | 受限于处理速度，容易阻塞             | **极高**，回调不阻塞，定时器可并行       |
| **CPU 占用**             | 处理时集中占用                       | 平均分布，更平滑                         |
| **丢帧/丢数据**          | 不会丢，但会导致背压（Backpressure） | 可能丢帧（新数据覆盖旧数据）             |
| **线程安全**             | 无共享数据，天然安全                 | **需要加锁**（`std::mutex`）保护共享缓存 |
| **代码复杂度**           | 简单                                 | 中等                                     |
| **典型应用**             | 急停按钮、简单状态机                 | 视觉里程计、激光雷达建图、控制闭环       |

回调函数中直接处理相当于中断，如果耗时长，就会影响整个系统。
定时器标志位固定频率轮询，系统略有延时，确定性、时间步长恒定，但是非常稳健

| 对比维度     | 回调直接处理                     | 定时器轮询                        |
| :----------- | :------------------------------- | :-------------------------------- |
| **你的类比** | **相当于中断**                   | **相当于主循环轮询**              |
| **响应方式** | 事件触发，抢占式                 | 时间触发，顺序执行                |
| **系统影响** | 耗时长则阻塞所有其他回调         | 执行时间固定，不影响其他回调      |
| **确定性**   | 响应时间不确定（受执行时间影响） | **执行周期完全确定**（固定的 dt） |
| **稳定性**   | 脆弱（容易雪崩）                 | **非常稳健**（隔离故障）          |
