# 项目工作约定

## 文档同步（每次代码更新后必须执行）

1. **自动同步更新相关文档**：README.md、以及受影响的配置说明（依赖、脚本、运行方式变化都要反映到文档）。
2. **在根目录 `zero.md` 追加更新记录**：只记「时间 + 更新内容」，一条一行，精简，不写过程分析。
3. **保持 `zero.md` 顶部的目录结构最新**（排除 node_modules、.nuxt、锁文件等生成物与隐藏目录）。

## 验证约定

- 默认只执行开发态验证（必要的 `pnpm typecheck`、复用 `http://localhost:5173` 的开发服务器与浏览器检查）。
- 未经用户明确要求，不再运行 `pnpm build`、`pnpm generate` 或生产预览；最终功能验收由用户手动完成。
- 开发态验证不得自动创建注册账号、发送非零速度、发起导航目标或修改远端业务数据。

## 设计规范

- 前端视觉遵循 `Design/modern.md`（现代简约）：留白优先、中性色 + 单一强调色、1px 细分割线、小圆角、轻阴影、以 8px 为间距基数。
- 当前阶段只做**单页面设计**，页面骨架：顶部导航（`.nav-left` / `.nav-right`）+ 内容区 `.zero` + 空页脚 `.site-footer`。概览页是单屏“操作席简报”：只读认证状态、按需建立的单一 SRS WHEP 视频预览与最近控制台会话电量/链路快照；地图与点云只在控制台内使用，概览不再读取地图 Canvas 或地图快照作为主视觉。导航与概览在桌面端共用 `1440px` 宽度，视频场景弹性占用简报剩余高度，窄屏切回紧凑单列；概览视频仅在激活时建立、离开时释放，控制台首次进入后由根级 `KeepAlive` 缓存，返回概览只暂停控制台舞台渲染/帧采样，不集中销毁 GPU、RTC 或 Hub；快照在内存即时更新、`sessionStorage` 最多约每秒合并写入一次，控制台真正卸载时落盘最后一帧，退出/注销时取消待写数据；`LAST SESSION` 只能说明最近一次控制台观测，控制台仍是视频、态势、感知和控制的唯一实时入口。
- 概览状态、图标入口与缓存说明使用统一 `Tooltip`（Reka UI），可键盘聚焦、触摸端不依赖 hover，Tooltip 只补充语义，不替代可见状态或告警。
- 控制台 HUD 遵循 `Design/console-hud.md` v3.21（FPS 式透明叠印：元素直接印在画面上不做卡壳；PiP 使用 `HudPanel bare` 开放式取景框；玻璃仅右侧控制台抽屉兜底且 ≤1 块，抽屉收起静止态必须透明无模糊，悬浮/聚焦预告后再双轴展开；视频/态势/感知设置、操作者状态与前端诊断统一放入该抽屉；进控制台收起 nav/footer，3 秒闲时完全隐藏 HUD，抽屉悬浮/聚焦/展开时暂停计时，Esc/左上开放式箭头退出；游戏化装饰只能取自其 §4 词汇表，每簇 ≤2 种、透明度 ≤0.25、禁循环动画；簇内间距 4/8/12/16、字号 9/11/13 三档）。

## 技术契约

- ROS2 话题契约：`interface.md`；2026-08-04 实测 `ws://192.168.1.30:9091` 可稳定订阅地图/里程计/RGB/电池，`9090` 曾拒绝后恢复，前端局域网摄像头默认值因此切到 `9091`，仍可用环境变量覆盖。`nuxt.config.ts` 与 `useLanCamera.ts` 的兜底值必须保持一致；机器人样例中的 `9090` 只作为原始基线，不得覆盖当前前端默认值。后端必须指向当时实际可用的 rosbridge 端口，不得仅凭 TCP 一次成功判定数据链正常
- 后端 REST / SignalR / SRS 契约与前端 SDK：`Backend/`（当前局域网联调默认 `http://192.168.1.139:5122`，可用 `NUXT_BACKEND_BASE_URL` 覆盖；SRS 签发回环地址时前端按后端主机归一化，可用 `NUXT_SRS_BASE_URL` 显式覆盖；无 Refresh Token，勿虚构 `/api/auth/refresh`）
- 视频三来源固定为：SRS WebRTC（WHEP）、Rosbridge（MapHub `CameraImage` 中转）、局域网（浏览器直连机器人 rosbridge）；切换来源必须释放上一条链路，不得把 `CameraImage` 继续作为 WHEP 隐式回退；SRS 只有收到可播放视频帧才允许标记 `LIVE`，不得把 PeerConnection 连通误报为已有画面。三来源连续 2.5 秒没有真实新帧时只能保留最后可见画面并标记本地 `frameHeld / FRAME HOLD`，下一真实帧到达后才恢复 `LIVE`；首帧等待、帧保持与连接错误必须分开呈现，`frameHeld` 不得被表述为视频服务、MapHub、ROS、TF 或机器人仍然在线
- 视频 FPS 只统计实际收到的媒体帧：WHEP 优先使用 `requestVideoFrameCallback`，不支持时采样 `getVideoPlaybackQuality().totalVideoFrames` 或 `webkitDecodedFrameCount`；Rosbridge/局域网只由实际 `CameraImage` 帧累计。两者都不可用时不显示误导数值，切源、断流和卸载时清空左下角读数；保持态必须停止 FPS 并在诊断中标记 `FRAME HOLD`
- WHEP 每次启动必须拥有独立本地代际；切源、换设备、重连或卸载后，旧的签发地址响应、PeerConnection 状态、媒体轨道和帧率回调不得改写当前 `video.srcObject`、来源读数、`LIVE` / `OFF` 或 FPS。该隔离只防止前端异步竞态，不等于已取消远端推流或确认网络状态
- 认证状态由 `app/composables/useAuth.ts` 统一管理；Access Token 与无密码会话元数据仅保存于同一标签页 `sessionStorage`，刷新前校验到期时间，关闭标签页、401、退出或到期清空会话；当前后端同账号再次登录会立即使旧 Token 返回 `401`，故 Postman、其他标签页或公网测试页不得与控制台共用管理员账号做并行登录验证；游客不连接 ChatHub/CommandHub，非游客仅在 `/api/operator/current` 返回 `isSelf=true` 时启用控制
- 操作者状态由 `app/composables/useRobot.ts` 的 `operatorState` 统一持有：登录后先请求 `/api/operator/current`，非游客只使用既有 ChatHub `OperatorChanged` 同步；操作者面板不得新建第二条 ChatHub。游客可显示初次查询到的状态，但不得建立操作者或控制连接
- 操作者面板独立于诊断中心：非管理员只读；仅 `system.admin` 可读取可分配账户、移交或回收操作权。移交/回收必须由用户在 4 秒内二次点击后才请求既有 REST 接口，前端不自动执行远端管理动作；账户列表、确认状态、邮箱和凭据均不得持久化或导出，后端鉴权是最终权限边界
- CommandHub 手动速度循环只能在 WASD / 摇杆有效输入期间运行；空闲、纯导航、初次连接及无手动输入的连接回收不得持续或额外发送零速到 `/manual_cmd_vel`。最后一个手动输入释放、手动驾驶中失焦或显式急停时才发送停车
- 桌面 WASD 必须按前后轴与转向轴独立合成：`WA / WD / SA / SD` 稳态同时提交非零 `linearX` 与 `angularZ`，不得拆为两个速度源。键盘转向采用速度斜坡：同向首次为 `±0.1 rad/s`，约 `0.5s` 升至常规目标 `±0.5 rad/s`；Shift 时目标为 `±1.0 rad/s`。`W+S` 或 `A+D` 抵消后视为无有效手动输入，不得维持或重启速度循环
- 前端线速度档位为常规 `0.5 m/s`、Shift/摇杆满量程请求 `1.0 m/s`；Shift 同时把键盘转向目标从 `±0.5 rad/s` 提至 `±1.0 rad/s`，但不得绕过速度斜坡；后端文档当前仍声明钳制 `0.5 m/s`，联调时不得把前端读数当作实车已达到 `1.0 m/s` 的证据
- MapHub 只能由 `useTelemetry.ts` 建立一条共享会话；顶部 `hud-tele` 通过 props 消费 Odometry / SafeTwist，不得另建 Hub。运动遥测最高 10Hz 更新 UI，2.5 秒无帧、重连或退出时清空为 `--`；自动重连不得清空已验证的静态 Map 或其帧指标。每次真实 `Map` 帧可按“后端地址 + 当前登录身份”写入 IndexedDB 静态快照，内容指纹变化后最多每 2 秒写一次；只保存已校验的 `MapFrame` 栅格，最多有效 7 天，不能保存 Token、位姿、路径、代价图、导航草案或其他动态遥测。退出登录必须清除该身份的本机地图快照；当前 MapHub 无设备 ID，不能假定快照可跨设备复用
- 顶部运动条必须把里程计源标为 `ODO`，缺失里程计而回退 `SafeTwist` 时标为 `SAFE`；`ODO` 的 X/Y/θ 不得当作地图 `RobotPose`，`SAFE` 是安全控制输出而非轮速实测。生命体征簇的 `CMD` 只表示前端请求线速度/上限，不能标作实际速度
- 地图舞台由 `MapStage.vue` 消费同一 MapHub 的栅格、位姿、路径、局部规划、扫描、粒子和代价地图帧；Canvas 按 ROS 世界坐标绘制并翻转 y 轴，扫描按离散点显示。机器人跟随只平移视图，中键拖拽/缩放退出跟随；轨迹最多保留 600 个采样点。图层新鲜/陈旧判断必须与诊断中心共用 `TELEMETRY_STALE_AFTER_MS`，静态 Map 不得判陈旧；首次登录或自动重连时可以先恢复本机 `CACHED` Map，但它只允许观察、平移和缩放，必须在当前连接收到新的真实 `Map` 帧后才解除 `SetGoal` / `SetInitialPose` 门控。首次订阅或自动重连后 1.5 秒仍未收到 Map 时仅可补订阅一次，随后必须呈现“未收到 Map 帧”或明确的解码错误，不得无限显示模糊等待态；后端未提供叠加层 `frame_id` 时，不得把局部层与扫描的对齐视为已验证
- 地图原始栅格位图、态势环境证据位图、全局代价、局部代价和地图增量必须分别失效；数据帧只标记对应缓存脏状态，并在下一次 `requestAnimationFrame` 合并处理最新帧，禁止任一图层更新时同步重建全部缓存。静态 Map 的原始几何签名、内容哈希和适配视图签名必须分离：内容未变时不得重建位图，Canvas 逐帧只消费缓存或按几何参数绘制态势场；仅原始几何变化时可重新适配视图并触发场景框入场。扫描与粒子绘制必须跨整帧均匀抽样，并维持固定的可见点上限；全局路径与局部规划同样必须限制显示密度（当前 4,000 / 2,400 点），保留 NaN 分段断开和每段首尾点，避免高频诊断图层拖慢驾驶视图。动态图层跨过既有陈旧阈值后仅可按低透明度显示，收到新帧后立即恢复；静态 Map、态势证据与本地轨迹不得被误标或降权，陈旧状态变化只可请求一次重绘，不得引入持续空转
- 地图主舞台是“环境证据 / 覆盖范围 / 行动 / 风险”的只读态势显示层：默认态势可以读取 `MapFrame.data` 做逐格证据着色，已知自由区域用浅色覆盖、未知格透明、占据值用深色标记；这些像素只表达已观测证据，绝不能被命名或绘制成物理墙体、自由地面、障碍或安全通道。覆盖范围、低对比米制参考网、虚线范围边和四角定位标记仅表达当前地图坐标的可观察范围。蓝色计划路径、青绿即时路线、低对比虚线轨迹、机器人定位环/朝向线、琥珀全局风险、红色近场风险、青绿 `MapPatch` 环境变化和场景读数都只能在 Canvas 绘制时产生，绝不能修改原始 `MapFrame`、占据格判断、路径数据或导航调用参数；`MapPatch` 只能独立叠加，不能合并回静态 Map 或被表述成导航真值。态势证据层不得做闭运算、蒙版、凸包、补线、插值、正交化、轮廓重建或假墙；无已知栅格时必须在场景上下文与 Canvas 场内显示 `NO ENV EVIDENCE`，不能把空态误报为连接失败。态势分支可直接按当前 `MapFrame` 几何绘制覆盖范围，不得因原始位图重建尚未完成而提前清空返回；解析预设或关闭“态势场”开关必须恢复原始像素栅格与工程网格。展示结果不得向 `MapFrame` 回写，也不得参与 `mapCellState()`、`goalBlockReason()`、`SetGoal`、`SetInitialPose`；路径的视觉宽线只用于读图层级，绝不能解释为可达性或导航置信度
- 地图抽屉必须保留会话级“态势 / 解析”观察预设：态势只默认显示环境、任务路径、即时路线与轨迹，路径风险、近场风险、扫描、定位分布、环境变化仅在解析预设中默认打开；图层手动改变后标记 `CUSTOM`。目标草案与提交可根据静态 Map 栅格拒绝 `occupancy ≥65` 的明显障碍，但未知格不可被前端伪装为不可达，最终规划/可达性仍属于后端导航栈
- 地图导航只通过 `useTelemetry.ts` 的现有 MapHub 调用 `SetGoal` / `SetInitialPose`。定位必须经过“初始位姿草案 → `SetInitialPose` 成功 → 操作者人工确认 → 导航就绪”，不得由 `RobotPose` 自动放行，也不得宣称有定位置信度；该本地确认仅留在当前页面会话，当前操作者失权时必须与本地选中状态一同复位。桌面浏览态固定为：左键点选机器人、中键按住拖拽平移、约 280ms 长按左键后拖拽框选；定位就绪后右键短点以“机器人→落点”作默认朝向，右键拖拽设精确朝向并在松开时提交单目标。`Shift + 右键`在接口没有队列/任务生命周期前只能保留本地草案，不得串发 `SetGoal`；`Esc`只取消本地草案或框选。提交必须受当前操作者与 `robot.control` 权限、MapHub 连接、地图范围、单一 in-flight 和短窗口重复目标去重共同门控。Hub 调用成功只可描述为“已提交到后端”；本地目标追踪必须显式标记“前端估算”，只允许显示已提交、检测到移动、接近目标、疑似停滞。“停止追踪”不得命名或实现为“取消导航”；当前无任务 ID、反馈、取消、队列和定位置信度接口
- 地图画布必须保留系统原生光标，不得在 Canvas 内隐藏、替代或模拟屏幕级指针；选中机器人、初始位姿草案、导航目标与落点反馈仍使用世界坐标。动画只可在 120–220ms 一次性反馈窗口请求帧；触控、抽屉与键盘可访问性不得依赖屏幕级光标
- 控制台与概览的根视图必须通过单实例 `KeepAlive` 切换：停用控制台时只能暂停点云 rAF/GPU 缓冲消费、地图 Canvas 重绘和视频 FPS 采样，不能在同一帧卸载 GPU、RTC、MapHub 与 CommandHub；重新激活时恢复当前会话，真正清理由登出、刷新或组件最终卸载承担。控制台停用时必须解绑全局键盘/焦点输入并停止已激活的手动速度循环，禁止隐藏态继续控制机器人。
- 点云舞台只使用 `/api/pointcloud/streams` 返回的流名，首次默认优先选择 topic `/scan`（或流名 `scan`），缺失时才回退 `points2` / 首个流；页面会话内可恢复首选流和视觉参数，显示上限恢复或切流时必须按该流 `maxPoints` 重新钳制。显示上限必须均匀采样整帧；实时入站帧只保留同一显示帧内最后一包，在单个 `requestAnimationFrame` 消费，数据 FPS 仍统计所有入站帧。真实可见帧可保留一份已筛选、已 LOD 的位置/颜色缓冲，且只能在相同身份与相同流的当前页面会话内恢复为 `CACHED`；不得写入 IndexedDB / localStorage，不得保留原始全量 `xyz`，切流或退出登录必须清除，首个新真实帧必须覆盖并恢复 `LIVE`。冻结只停止可见缓冲更新且不停止链路监测；暂停、切流、重连和卸载必须取消待消费帧，防止旧流覆盖新画面。订阅成功不等于 `LIVE`，收到首帧后才进入 `ok`；订阅后 3 秒仍未收到首帧时必须显示 `HUB · NO FRAME` / 诊断 `NO FRAME`，不能无限展示连接动画或把它归为认证、空回波或渲染错误；连续 2.5 秒无新帧时只能保留现有可见缓冲并标记本地 `frameHeld / FRAME HOLD`，下一真实帧到达后才恢复 `LIVE`。首帧等待、原始帧零点、筛选后零点、帧保持、会话缓存与连接错误必须分别呈现；`frameHeld` 或 `CACHED` 只能进入本地 HUD/诊断，绝不表示 ROS、MapHub、TF 或机器人仍在实时更新。返回概览时缓存现有渲染器并暂停 rAF/缓冲消费，重新进入时只恢复当前帧；正常舞台切换仅 `dispose()` Three.js 资源，禁止调用 `forceContextLoss()`；创建、Resize、渲染或 `webglcontextlost` 失败时必须取消 rAF/待消费帧、停止 PointCloudHub、设为本地 `OFF` 错误并在 15 秒冷却内拒绝重复创建，不能由重连或舞台重挂载形成 WebGL 申请循环。点云像素比最高 `1.5`；缺少 TF 时不得实现多帧累积或声称已完成空间融合
- 点云 `auto` 观察预设必须对 `/scan` 使用俯视、对非扫描流使用三维视角；用户拖拽视角后标记 `CUSTOM`。距离/高度筛选默认关闭，开启后必须从实际消费的同一帧统计原始、有限和筛后点数，再跨筛后全帧均匀 LOD；筛选参数必须在单帧处理前固化，范围筛选用平方距离比较，完整筛后范围用于自动适配和高度/距离着色，属性缓冲仅上传实际可见 LOD 区段。质量读数、诊断快照与 PLY/CSV 元数据必须共用这组真值。单色模式必须使用材质统一颜色并跳过顶点颜色缓冲写入，只有高度/距离着色才启用顶点颜色。暂停时视觉参数变更只能重算当前可见帧，不得消费暂停后的网络帧。无新帧且相机静止时不得保持连续 WebGL 动画帧，只有新点云、交互、尺寸或可视化参数变化才可请求绘制
- 点云首视图默认隐藏工程网格、坐标轴和背景格；`/scan` 俯视只允许显示随可见范围缩放的本地感知环、边缘刻度与原点环，切出扫描态后恢复用户的辅助线偏好。该参考层仅表达传感器局部空间，绝不与地图硬融合、绝不伪装为真实三维数字孪生；缺少可靠 `frame_id` / TF 时不得实现跨帧累积或跨源空间对齐
- 前端诊断中心必须复用现有 API / CommandHub / MapHub / 视频 / PointCloudHub 状态，不得另建诊断连接；当前连接的静态 Map 标为 `STATIC`，仅从 IndexedDB 恢复的地图标为 `CACHED`，两者不能因不持续更新而判定 `STALE`；视频与点云的 `frameHeld` 以及点云会话快照的 `CACHED` 必须在媒体行可见，不能被伪装为 FPS 或在线状态；Map 二进制帧解码异常与一次缓存补订阅后仍无帧必须进入 MapHub 最近错误。诊断导出只能包含本地运行指标、缓存来源与错误，不得包含 Access Token、SignalR 查询串或密码
- 会话级 UI 偏好使用 Nuxt `useState`，仅保留抽屉页签、媒体来源和地图（含态势场开关）/点云显示参数；不得持久化暂停态、轨迹、错误、导航目标或任何远端任务状态，也不得改用 `localStorage` 延长其生命周期。受控例外仅为：无密码的 `AuthSession`（Access Token、过期时间、身份、权限）写入同一标签页 `sessionStorage` 以支持刷新恢复；静态 Map 通过 IndexedDB 以受作用域、受时限的本地观测快照保存；点云通过 `useState` 以受显示上限的会话缓冲保存。三者都不得参与控制或导航真值，登出、到期或无效解析必须清除认证会话
- 前端：Nuxt 4 + Vue 3 + TypeScript + Tailwind v4 + shadcn-vue（Reka UI），包管理 pnpm，源码在 `Frontend/app/`
- Nuxt Icon 使用本地 `lucide` / `game-icons` 数据；保留 `icon.clientBundle.scan=true` 与 `eye`、`eye-off`、`log-in` 显式预打包，避免 SSR 首屏退回外部 Iconify 请求并产生加载告警
- 认证 API 统一使用 `60_000ms` 超时，局域网认证响应变慢时不得沿用媒体或设备查询的 8 秒超时；Access Token 只允许连同无密码会话元数据写入同标签页 `sessionStorage`，刷新时需先校验 `expiresAt`，关闭标签页、登出或到期必须清除。认证客户端处理 `401` 时只可注销与其创建时一致的 Token，不能让旧请求清掉新会话
- 设计令牌集中在 `Frontend/app/assets/css/main.css`（命名对齐 shadcn 变量，含 `.dark` 暗色占位）；动画分层：CSS/`<Transition>` 打底 → motion-v 弹簧微交互 → GSAP 时间线编排
- shadcn 组件在 `app/components/ui/`（无前缀自动导入）；组件 props 勿直接 `extends` 包内导入类型（`@vue/compiler-sfc` 无法解析，需本地内联声明）
